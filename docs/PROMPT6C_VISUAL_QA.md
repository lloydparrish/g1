# Prompt 6C — UI Text, Divider and Journey Map QA

Prompt 6C is the current acceptance record for the final HUD polish. The main change is a strict knowledge boundary: the persistent World Map records only the selected run route and current map; the post-objective destination picker is the only UI that reveals generated choices.

## Text and spacing

- Shared tooltip layout wraps names, metadata, descriptions and requirements to a bounded width, measures the resulting height, and positions the full tooltip inside the viewport. Short copy stays compact. The focused long-description capture uses Demonic Gateway.
- Toolbar names wrap to two measured, centered lines before ellipsis. Resource costs, action time and item quantity occupy a consistent detail area beneath the name. Items show their count and authoritative use time (70 for consumables; the authored ability time for scrolls).
- Timeline and Field Intelligence sections flow from measured header/body positions. The header rule has padding above and below it; objective copy and recent-event content determine following positions.
- World Map node names are measured and limited to two lines. The status/footer is separated from the winding route and the panel border.

## Journey map visibility and authority

The persistent map derives its ordered nodes from `run.route` and `run.stage_id`. It contains circular nodes joined by a winding connector, distinguishes completed nodes from the current node, and adds an unlabeled `?` node while normal progression remains. At 6/6, no unknown node is added. Repeated stage names remain repeated when the actual run history visits that stage again.

The persistent map does not read `route_choices`, create destination hit targets, attach future descriptions, or expose candidate IDs in tooltips. The picker reads the real choices after objective completion. `choose_route` appends only the selected stage to the authoritative route; the rejected choice remains absent. Boss entry records the visited `graveyard` map ID; legacy saves with the old `grave_tyrant` route value are normalized for display.

Automated checks assert that generated choices are absent from persistent map hit targets, history is ordered from run state, only the chosen destination joins the route, the picker owns post-objective choice, and 5/6 and 6/6 states render the expected unknown-node behavior. No hidden destination is accessible through the persistent map UI. The simulation may hold generated choices internally until the picker opens.
